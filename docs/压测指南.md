# 压测指南

## 环境概览

### 服务架构

```
Client ──TCP──> Gate ──UDS──> RouterAgent ──TCP──> RouterAgent ──UDS──> Lobby
   ↑                                                                    │
   └──────────────────── 响应原路返回 ─────────────────────────────────────┘
```

- **Gate** (gatesvr)：客户端 TCP 接入，nodeid=77.1.1，监听 0.0.0.0:7001
- **RouterAgent** (routeragent)：sidecar 路由代理，nodeid=77.6.1
- **Lobby** (lobbysvr)：业务逻辑，nodeid=77.2.1

### 当前配置参数

| 服务 | 配置项 | 值 |
|------|-------|----|
| Gate | listen_tcp | 0.0.0.0:7001 |
| Gate | routeragent_sock_path | /tmp/routeragent/ra.sock |
| Lobby | routeragent_sock_path | /tmp/routeragent/ra.sock |
| RouterAgent | sock_path | /tmp/routeragent/ra.sock |
| RouterAgent | listen_addr | 10.160.88.170:7100 |

### 测试工具

`tools/client_sim/main.go` — 模拟客户端发送 Ping 请求并统计 QPS/延迟。

编译：
```bash
go build -o /tmp/client_sim ./tools/client_sim/
```

参数说明：
```
--addr           服务地址（默认 127.0.0.1:7001）
--clients        并发连接数（>1 开启压测模式）
--requests       每连接请求数
--timeout        超时时间（默认 3s）
--quiet          静默错误输出
--report-every   定时报告间隔（如 1s）
```

## 一、单机测试

### 1.1 部署说明

单机模式下，gate、routeragent、lobby 三个进程都在同一台机器上。gate 和 lobby 共享**同一个** RouterAgent 的 UDS socket。当 gate 请求 lobby 时，RA 发现 lobby 的 UDS 连接在本地，直接通过 UDS 转发，**不走 TCP**。

### 1.2 启动服务

```bash
cd /home/debian/BidServer

# 独占测试环境可以使用项目脚本；共享环境应只停止本次要测的目标进程。
# 精确停止示例：优先使用对应 bin 目录下的 pid 文件。
for f in run/gatesvr/bin/gatesvr.pid run/lobbysvr/bin/lobbysvr.pid run/routeragent/bin/routeragent.pid; do
  [ -f "$f" ] && kill -TERM "$(cat "$f")" 2>/dev/null || true
done

# 重新编译（如有代码改动）
go build -o /home/debian/BidServer/run/gatesvr/bin/gatesvr ./cmd/gatesvr/
go build -o /home/debian/BidServer/run/lobbysvr/bin/lobbysvr ./cmd/lobbysvr/
go build -o /home/debian/BidServer/run/routeragent/bin/routeragent ./cmd/routeragent/

# 精确启动本次测试需要的服务
cd /home/debian/BidServer/run/routeragent/bin
./routeragent --pid-file routeragent.pid --nodeid 77.6.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --routeragent-config ../conf/routeragent.yaml &

cd /home/debian/BidServer/run/gatesvr/bin
./gatesvr --pid-file gatesvr.pid --nodeid 77.1.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --gate-config ../conf/gate.yaml &

cd /home/debian/BidServer/run/lobbysvr/bin
./lobbysvr --pid-file lobbysvr.pid --nodeid 77.2.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --lobby-config ../conf/lobby.yaml &
```

### 1.3 确认服务正常

```bash
# 检查进程
pgrep -a 'gatesvr|lobbysvr|routeragent'

# 确认配置正确
grep routeragent_sock /home/debian/BidServer/run/lobbysvr/conf/lobby.yaml
# 应输出: routeragent_sock_path: "/tmp/routeragent/ra.sock"

# 烟雾测试
/tmp/client_sim --timeout 10s
# 应输出: tong recv seq=1 cmd=2055 text="tong:ping" latency=xxxµs
```

### 1.4 执行压测

```bash
# 100 客户端 × 1000 请求（最佳 QPS 区间）
/tmp/client_sim --clients 100 --requests 1000 --quiet --report-every 1s

# 200 客户端 × 1000 请求
/tmp/client_sim --clients 200 --requests 1000 --quiet --report-every 1s

# 500 客户端 × 500 请求（重负载）
/tmp/client_sim --clients 500 --requests 500 --quiet --report-every 1s

# 1000 客户端 × 300 请求（极限并发）
/tmp/client_sim --clients 1000 --requests 300 --quiet --report-every 1s
```

### 1.5 预期结果

作为参考基准（优化后代码）：

| 客户端数 | QPS | p50 | p90 | p99 |
|----------|-----|-----|-----|-----|
| 50 | ~31,000 | 0.7ms | 4.0ms | 12ms |
| 100 | ~32,000 | 1.6ms | 7.7ms | 18ms |

## 二、跨机测试（单机模拟）

### 2.1 原理

在同一台机器上启动**两个 RouterAgent 实例**（RA1 和 RA2），分别服务于 gate 和 lobby。当 gate 请求 lobby 时，RA1 发现 lobby 不是本地连接，通过 **TCP** 连接 RA2 转发请求。

```
Gate ──UDS──> RA1 ═══TCP═══> RA2 ──UDS──> Lobby
```

这与真实跨机器部署等价——唯一的差别是 TCP 走的是 loopback 而不是物理网络，但整个转发链路相同。

### 2.2 配置文件准备

#### RA2 配置目录

```bash
# 创建目录
mkdir -p /home/debian/BidServer/run/routeragent2/{bin,conf,log}

# 复制二进制
cp /home/debian/BidServer/run/routeragent/bin/routeragent \
   /home/debian/BidServer/run/routeragent2/bin/routeragent

# RA2 配置文件: /home/debian/BidServer/run/routeragent2/conf/routeragent.yaml
cat > /home/debian/BidServer/run/routeragent2/conf/routeragent.yaml << 'EOF'
sock_path: "/tmp/ra2.sock"
listen_addr: "127.0.0.1:7101"
heartbeat_sec: 30

logger_group:
  main:
    level: info
    format: console
    stderr_also: true
    dir: "../log"
    basename: routeragent2
    max_size_mb: 100
    max_backups: 72
    rotate_by_hour: true
  res:
    level: info
    format: console
    stderr_also: true
    dir: "../log"
    basename: routeragent2_res
    max_size_mb: 100
    max_backups: 72
    rotate_by_hour: true
  tracing:
    level: info
    format: console
    stderr_also: true
    dir: "../log"
    basename: routeragent2_tracing
    max_size_mb: 100
    max_backups: 72
    rotate_by_hour: true
EOF
```

#### 修改 lobby 指向 RA2

```bash
# 编辑 /home/debian/BidServer/run/lobbysvr/conf/lobby.yaml
# 把: routeragent_sock_path: "/tmp/routeragent/ra.sock"
# 改为: routeragent_sock_path: "/tmp/ra2.sock"

sed -i 's|routeragent_sock_path:.*|routeragent_sock_path: "/tmp/ra2.sock"|' \
  /home/debian/BidServer/run/lobbysvr/conf/lobby.yaml
```

### 2.3 启动服务

```bash
cd /home/debian/BidServer/run

# 精确停止本次跨机模拟涉及的进程，避免影响同机其他测试任务。
for f in routeragent/bin/routeragent.pid routeragent2/bin/routeragent2.pid gatesvr/bin/gatesvr.pid lobbysvr/bin/lobbysvr.pid; do
  [ -f "$f" ] && kill -TERM "$(cat "$f")" 2>/dev/null || true
done

# 清理残留 PID
rm -f routeragent/bin/routeragent.pid routeragent2/bin/routeragent2.pid gatesvr/bin/gatesvr.pid lobbysvr/bin/lobbysvr.pid

# 启动 RA1（gate 侧，nodeid=77.6.1，listen=10.160.88.170:7100）
cd routeragent/bin
./routeragent --pid-file routeragent.pid --nodeid 77.6.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --routeragent-config ../conf/routeragent.yaml &

# 启动 RA2（lobby 侧，nodeid=77.6.2，listen=127.0.0.1:7101）
cd ../../routeragent2/bin
./routeragent --pid-file routeragent2.pid --nodeid 77.6.2 --daemon \
  --common-config ../../common/conf/common.yaml \
  --routeragent-config ../conf/routeragent.yaml &

# 启动 gate（不变）
cd ../../gatesvr/bin
./gatesvr --pid-file gatesvr.pid --nodeid 77.1.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --gate-config ../conf/gate.yaml &

# 启动 lobby（现在连接 RA2）
cd ../../lobbysvr/bin
./lobbysvr --pid-file lobbysvr.pid --nodeid 77.2.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --lobby-config ../conf/lobby.yaml &

# 等几秒让服务发现完成
sleep 3
```

### 2.4 确认跨机路由生效

```bash
# 检查 4 个进程都在运行
pgrep -a 'gatesvr|lobbysvr|routeragent'
# 应看到 4 个进程：RA1(nodeid=77.6.1)、RA2(nodeid=77.6.2)、gate、lobby

# 烟雾测试
/tmp/client_sim --timeout 10s
# 应输出: tong recv seq=1 cmd=2055 text="tong:ping" latency=xxxµs
# 单次延迟应比单机模式高 ~250µs（TCP 往返）
```

### 2.5 执行压测

与单机相同命令：

```bash
/tmp/client_sim --clients 100 --requests 1000 --quiet --report-every 1s
/tmp/client_sim --clients 200 --requests 1000 --quiet --report-every 1s
/tmp/client_sim --clients 500 --requests 500 --quiet --report-every 1s
```

### 2.6 预期结果

作为参考基准（优化后代码）：

| 客户端数 | QPS | p50 | p90 | p99 |
|----------|-----|-----|-----|-----|
| 100 | ~28,000 | 1.8ms | 8.9ms | 18ms |
| 200 | ~30,000 | 4.9ms | 14ms | 21ms |
| 500 | ~29,000 | 15ms | 28ms | 42ms |

**单机 vs 跨机差异约为 7-13%**，来自 RA1→RA2 之间的 TCP 往返。

  [ -f "$f" ] && kill -TERM "$(cat "$f")" 2>/dev/null || true
done

# 删除 RA2
rm -rf /home/debian/BidServer/run/routeragent2

# 恢复 lobby 配置

## 三、解读压测输出

```text
progress sent=63541 ok=63441 failed=0 qps=31714.81 elapsed=2s

benchmark done addr=127.0.0.1:7001 clients=100 requests_per_client=1000
  sent=100000 ok=100000 failed=0 elapsed=3.092s qps=32346.48

latency min=32µs avg=3.053ms p50=1.619ms p90=7.714ms p99=17.563ms max=23.93ms
```

- **qps** = 成功请求数 / 总时间。压力不饱和 (<50 客户端) 时偏低是正常现象。
- **p50** = 中位数延迟，表示一半请求的响应时间。
- **p99** = 99% 的请求在此延迟内完成。超过 100ms 需关注。
- **failed > 0** = 有失败，查看失败类型（connect/send/read/err_code 等）。

### 常见失败原因

| 失败类型 | 含义 | 排查方向 |
|----------|------|--------|
| connect | TCP 连接失败 | gate 未启动或端口不对 |
| send/read | 收发超时 | 服务过载，降低客户端数 |
| err_code | 业务返回错误码 | 查看 lobby/gate 日志 |
| payload_mismatch | 回包内容不对 | 协议版本不匹配 |

## 四、常见问题

### Q: 启动后连接 refused
A: gate 未启动或端口被占用。检查：
```bash
pgrep -a gatesvr
ss -tlnp | grep 7001
```

### Q: 烟雾测试 OK 但压测有大量失败
A: 服务过载或 etcd 不可达。
- 降低 `--clients` 值逐步排查。
- 检查 `/home/debian/BidServer/run/*/log/` 下的日志。

### Q: 跨机模式下 RA2 不转发
A: etcd 发现可能未完成。确认两个 RA 都已注册：
```bash
# 看 RA 日志是否都有 "etcd self register done"
grep "etcd" /home/debian/BidServer/run/routeragent/log/routeragent*.log
grep "etcd" /home/debian/BidServer/run/routeragent2/log/routeragent2*.log
```

### Q: 想用真正两个物理机器测试
A: 把 RA2 放在第二台机器上，修改 lobby 配置的 `routeragent_sock_path` 指向本机 RA 的 socket。保持 etcd 集群配置相同即可。

### Q: 压测客户端本身成为瓶颈
A: client_sim 工具是同步阻塞模型，每个连接一个 goroutine。瓶颈通常在 50K+ QPS 以上才出现。如果怀疑客户端瓶颈，可以在另一台机器上运行 client_sim。
