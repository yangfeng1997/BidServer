# 压测指南

## 环境概览

### 服务架构

```
Client ──TCP──> Gate ──UDS──> RouterAgent ──TCP──> RouterAgent ──UDS──> Lobby
   ↑                                                                    │
   └──────────────────── 响应原路返回 ─────────────────────────────────────┘
```

- **Gate** (gatesvr)：客户端 TCP 接入，nodeid=77.1.1，监听 0.0.0.0:7001
- **RouterAgent** (routeragent)：sidecar 路由代理，nodeid=77.6.1
- **Lobby** (lobbysvr)：业务逻辑，nodeid=77.2.1

### 当前配置参数

| 服务 | 配置项 | 值 |
|------|-------|----|
| Gate | listen_tcp | 0.0.0.0:7001 |
| Gate | routeragent_sock_path | /tmp/routeragent/ra.sock |
| Lobby | routeragent_sock_path | /tmp/routeragent/ra.sock |
| RouterAgent | sock_path | /tmp/routeragent/ra.sock |
| RouterAgent | listen_addr | 单机默认见配置；本机双 RA 压测使用 127.0.0.1:7100 / 127.0.0.1:7101 |

### 测试工具

`tools/client_sim/main.go` — 模拟客户端发送 Ping 请求并统计 QPS/延迟。

编译：
```bash
go build -o /tmp/client_sim ./tools/client_sim/
```

参数说明：
```
--addr           服务地址（默认 127.0.0.1:7001）
--clients        并发连接数（>1 开启压测模式）
--requests       每连接请求数
--timeout        超时时间（默认 3s）
--quiet          静默错误输出
--report-every   定时报告间隔（如 1s）
```

## 一、单机测试

### 1.1 部署说明

单机模式下，gate、routeragent、lobby 三个进程都在同一台机器上。gate 和 lobby 共享**同一个** RouterAgent 的 UDS socket。当 gate 请求 lobby 时，RA 发现 lobby 的 UDS 连接在本地，直接通过 UDS 转发，**不走 TCP**。

### 1.2 启动服务

```bash

# 精确停止示例：优先使用对应 bin 目录下的 pid 文件。
for f in run/gatesvr/bin/gatesvr.pid run/lobbysvr/bin/lobbysvr.pid run/routeragent/bin/routeragent.pid; do
  [ -f "$f" ] && kill -TERM "$(cat "$f")" 2>/dev/null || true
done

# 重新编译（如有代码改动）
go build -o /home/debian/BidServer/run/gatesvr/bin/gatesvr ./cmd/gatesvr/
go build -o /home/debian/BidServer/run/lobbysvr/bin/lobbysvr ./cmd/lobbysvr/
go build -o /home/debian/BidServer/run/routeragent/bin/routeragent ./cmd/routeragent/

# 精确启动本次测试需要的服务
cd /home/debian/BidServer/run/routeragent/bin
./routeragent --pid-file routeragent.pid --nodeid 77.6.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --routeragent-config ../conf/routeragent.yaml &

cd /home/debian/BidServer/run/gatesvr/bin
./gatesvr --pid-file gatesvr.pid --nodeid 77.1.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --gate-config ../conf/gate.yaml &

cd /home/debian/BidServer/run/lobbysvr/bin
./lobbysvr --pid-file lobbysvr.pid --nodeid 77.2.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --lobby-config ../conf/lobby.yaml &
```

### 1.3 确认服务正常


## 二、跨机测试（单机模拟）

### 2.1 原理

在同一台机器上启动**两个 RouterAgent 实例**（RA1 和 RA2），分别服务于 gate 和 lobby。当 gate 请求 lobby 时，RA1 发现 lobby 不是本地连接，通过 **TCP** 连接 RA2 转发请求。

```
Gate ──UDS──> RA1 ═══TCP═══> RA2 ──UDS──> Lobby
```

这与真实跨机器部署等价——唯一的差别是 TCP 走的是 loopback 而不是物理网卡和交换机，但整个 RouterAgent 跨节点转发链路相同。日常优化 RouterAgent 协议、队列、seq 映射、响应优先级、batch 写时，优先使用这种本机双 RA 压测；只有验证真实网络抖动、跨机 RTT、网卡/虚拟化开销时，才需要复制到两台物理机或虚拟机。

本机模拟时建议固定：

| 进程 | nodeid | UDS | RA listen | run 目录 |
|---|---|---|---|---|
| RA1（gate 侧） | `77.6.1` | `/tmp/ra1.sock` | `127.0.0.1:7100` | `run/routeragent/` |
| RA2（lobby 侧） | `77.6.2` | `/tmp/ra2.sock` | `127.0.0.1:7101` | `run/routeragent2/` |
| gatesvr | `77.1.1` | 连接 `/tmp/ra1.sock` | - | `run/gatesvr/` |
| lobbysvr | `77.2.1` | 连接 `/tmp/ra2.sock` | - | `run/lobbysvr/` |

目录约定：复用现有 `run/routeragent/` 作为 RA1，不再额外复制 `routeragent1`；只新增 `run/routeragent2/` 作为 RA2。每个进程目录独立维护 `bin/`、`conf/`、`log/` 和自己的 pid 文件，方便排查 RA1、RA2、gate、lobby 各自的日志和队列水位。

推荐结构：

```text
run/
  common/
    conf/common.yaml

  routeragent/       # RA1，gate 侧，复用现有目录
    bin/routeragent
    conf/routeragent.yaml
    conf/routeragent.local-cross.yaml
    log/

  routeragent2/      # RA2，lobby 侧，新增目录
    bin/routeragent
    conf/routeragent.yaml
    log/

  gatesvr/
    bin/gatesvr
    conf/gate.yaml
    conf/gate.local-cross.yaml
    log/

  lobbysvr/
    bin/lobbysvr
    conf/lobby.yaml
    conf/lobby.local-cross.yaml
    log/
```

### 2.2 配置文件准备

#### 准备 RA1 / RA2 / gate / lobby 配置

下面命令会在 `run/` 下创建本机双 RouterAgent 压测用配置，不需要改 `config/` 源文件。

```bash
cd /home/debian/BidServer

# 编译本次压测要用的二进制
go build -o run/routeragent/bin/routeragent ./cmd/routeragent/
go build -o run/gatesvr/bin/gatesvr ./cmd/gatesvr/
go build -o run/lobbysvr/bin/lobbysvr ./cmd/lobbysvr/
go build -o /tmp/client_sim ./tools/client_sim/

# 创建 RA2 目录，并复制 routeragent 二进制
mkdir -p run/routeragent2/{bin,conf,log}
cp run/routeragent/bin/routeragent run/routeragent2/bin/routeragent

# RA1 配置：gate 侧 RouterAgent
cp run/routeragent/conf/routeragent.yaml run/routeragent/conf/routeragent.local-cross.yaml
sed -i 's|sock_path:.*|sock_path: "/tmp/ra1.sock"|' run/routeragent/conf/routeragent.local-cross.yaml
sed -i 's|listen_addr:.*|listen_addr: "127.0.0.1:7100"|' run/routeragent/conf/routeragent.local-cross.yaml

# RA2 配置：lobby 侧 RouterAgent
cp run/routeragent/conf/routeragent.yaml run/routeragent2/conf/routeragent.yaml
sed -i 's|sock_path:.*|sock_path: "/tmp/ra2.sock"|' run/routeragent2/conf/routeragent.yaml
sed -i 's|listen_addr:.*|listen_addr: "127.0.0.1:7101"|' run/routeragent2/conf/routeragent.yaml
sed -i 's|basename: routeragent|basename: routeragent2|g' run/routeragent2/conf/routeragent.yaml

# gate 连接 RA1
cp run/gatesvr/conf/gate.yaml run/gatesvr/conf/gate.local-cross.yaml
sed -i 's|routeragent_sock_path:.*|routeragent_sock_path: "/tmp/ra1.sock"|' run/gatesvr/conf/gate.local-cross.yaml

# lobby 连接 RA2
cp run/lobbysvr/conf/lobby.yaml run/lobbysvr/conf/lobby.local-cross.yaml
sed -i 's|routeragent_sock_path:.*|routeragent_sock_path: "/tmp/ra2.sock"|' run/lobbysvr/conf/lobby.local-cross.yaml
```

> 注意：本机双 RA 模拟依赖 etcd 服务发现。RA1 和 RA2 必须使用同一份 `common.yaml`，并且两个 RA 的 `listen_addr` 都要能注册到 etcd；本机测试时使用 `127.0.0.1:7100` / `127.0.0.1:7101` 即可。

### 2.3 启动服务

```bash
cd /home/debian/BidServer/run

# 精确停止本次跨机模拟涉及的进程，避免影响同机其他测试任务。
for f in routeragent/bin/routeragent.pid routeragent2/bin/routeragent2.pid gatesvr/bin/gatesvr.pid lobbysvr/bin/lobbysvr.pid; do
  [ -f "$f" ] && kill -TERM "$(cat "$f")" 2>/dev/null || true
done

# 清理残留 PID
rm -f routeragent/bin/routeragent.pid routeragent2/bin/routeragent2.pid gatesvr/bin/gatesvr.pid lobbysvr/bin/lobbysvr.pid

# 启动 RA1（gate 侧，nodeid=77.6.1，listen=127.0.0.1:7100）
cd routeragent/bin
./routeragent --pid-file routeragent.pid --nodeid 77.6.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --routeragent-config ../conf/routeragent.local-cross.yaml \
  --pprof --pprof-addr 127.0.0.1:6061 &

# 启动 RA2（lobby 侧，nodeid=77.6.2，listen=127.0.0.1:7101）
cd ../../routeragent2/bin
./routeragent --pid-file routeragent2.pid --nodeid 77.6.2 --daemon \
  --common-config ../../common/conf/common.yaml \
  --routeragent-config ../conf/routeragent.yaml \
  --pprof --pprof-addr 127.0.0.1:6062 &

# 启动 gate（连接 RA1）
cd ../../gatesvr/bin
./gatesvr --pid-file gatesvr.pid --nodeid 77.1.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --gate-config ../conf/gate.local-cross.yaml \
  --pprof --pprof-addr 127.0.0.1:6063 &

# 启动 lobby（连接 RA2）
cd ../../lobbysvr/bin
./lobbysvr --pid-file lobbysvr.pid --nodeid 77.2.1 --daemon \
  --common-config ../../common/conf/common.yaml \
  --lobby-config ../conf/lobby.local-cross.yaml \
  --pprof --pprof-addr 127.0.0.1:6064 &

# 等几秒让服务发现完成；共享 etcd 下旧 lease 可能还没过期，建议至少等 10 秒后再重启同 nodeid
sleep 10
```

注意事项：

- 两个 RouterAgent 的 `listen_addr`、`--pprof-addr`、`sock_path`、`pid-file` 和日志 basename 都必须不同；任意一个重复都可能导致进程启动失败或日志混在一起。
- RouterAgent 自身注册使用 CAS，旧进程刚停时 etcd lease 可能还没回收，同一个 nodeid 立刻重启会报 `etcd node already exists`。遇到这种情况不要反复启动，等 10 秒左右让旧 lease 过期，或确认旧 key 已删除后再启动。
- 如果看到日志里 `etcd self register done`，但随后 Go client 查询同一前缀 `count=0`，通常是进程已经退出或 lease keepalive 断开，etcd 删除了租约上的 key。排查时同时看 `etcd keepalive failed`、`etcd lease recover done`、`etcd watch delete` 和当前 `ps` 进程列表。
- 当前 RouterAgent 使用周期性 `KeepAliveOnce` 保活；保活失败时会重新申请 lease，并把本 RA 已注册的 RouterAgent / 业务节点重新写回 etcd。压测前仍建议先用探针确认前缀下有 RA1、RA2、gate、lobby 四个 key。
- 启动顺序建议保持 `RA1 -> RA2 -> gate -> lobby` 或 `RA1/RA2 -> gate/lobby`，业务进程连接本侧 RA 成功后会由本侧 RA 代注册业务节点。

## 三、解读压测输出

```text
progress sent=63541 ok=63441 failed=0 qps=31714.81 elapsed=2s

benchmark done addr=127.0.0.1:7001 clients=100 requests_per_client=1000
  sent=100000 ok=100000 failed=0 elapsed=3.092s qps=32346.48

latency min=32µs avg=3.053ms p50=1.619ms p90=7.714ms p99=17.563ms max=23.93ms
```

- **qps** = 成功请求数 / 总时间。压力不饱和 (<50 客户端) 时偏低是正常现象。
- **p50** = 中位数延迟，表示一半请求的响应时间。
- **p99** = 99% 的请求在此延迟内完成。超过 100ms 需关注。
- **failed > 0** = 有失败，查看失败类型（connect/send/read/err_code 等）。

### 常见失败原因

| 失败类型 | 含义 | 排查方向 |
|----------|------|--------|
| connect | TCP 连接失败 | gate 未启动或端口不对 |
| send/read | 收发超时 | 服务过载，降低客户端数 |
| err_code | 业务返回错误码 | 查看 lobby/gate 日志 |
| payload_mismatch | 回包内容不对 | 协议版本不匹配 |

## 四、常见问题

### Q: 启动后连接 refused
A: gate 未启动或端口被占用。检查：
```bash
pgrep -a gatesvr
ss -tlnp | grep 7001
```

### Q: 烟雾测试 OK 但压测有大量失败
A: 服务过载或 etcd 不可达。
- 降低 `--clients` 值逐步排查。
- 检查 `/home/debian/BidServer/run/*/log/` 下的日志。

### Q: 跨机模式下 RA2 不转发
A: etcd 发现可能未完成。确认两个 RA 都已注册：
```bash
# 看 RA 日志是否都有 "etcd self register done"
grep "etcd" /home/debian/BidServer/run/routeragent/log/routeragent*.log
grep "etcd" /home/debian/BidServer/run/routeragent2/log/routeragent2*.log
```

### Q: 想用真正两个物理机器测试
A: 把 RA2 放在第二台机器上，修改 lobby 配置的 `routeragent_sock_path` 指向本机 RA 的 socket。保持 etcd 集群配置相同即可。

### Q: 压测客户端本身成为瓶颈
A: client_sim 工具是同步阻塞模型，每个连接一个 goroutine。瓶颈通常在 50K+ QPS 以上才出现。如果怀疑客户端瓶颈，可以在另一台机器上运行 client_sim。
